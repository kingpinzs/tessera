# Phase 05 — W10M keyboard (shell-owned IME)

## Goal
A W10M (final release) keyboard ships inside the shell APK as an input method, is enabled and selected through the onboarding
checklist, and types correctly in any app with the W10M layout, motion and behaviours ruled in the interview. Its window uses RV10
density.

## Scope
**In:** InputMethodService; W10M layouts (letters, numbers/symbols, per-input-type variants; geometry and motion values from R6 §2, see Decisions: R3 has no keyboard row); behaviours ruled in the interview; Settings page + checklist rows (IME enabled, IME selected); reuse of Apache-2.0 FlorisBoard code allowed inside the APK.
**Out (explicitly):** a separately installed keyboard or theme (RV1); cloud features; online dictionaries.

## Edge cases
- Password fields: no suggestions, no learning
- Keyguard password entry; IME crash on the keyguard and recovery through Android's IME switcher (m9)
- Landscape apps on a portrait-only shell
- Keyboard raised by the space-bar drag in a field near the bottom of the screen; handedness changed while the dot is held; an emoji inserted with "Switch back to letters" on while a category other than recent is showing
- IME crash → system fallback keyboard, then recovery
- Clipboard paste; very long text; fields with input filters
- Swipe over non-dictionary words; very fast swipes
- Microphone permission denied or in use by a call during voice typing
- Voice typing invoked while Cortana is listening (one engine, one microphone: the second caller waits or is refused with a notice, never a crash); the IME's voice key while another app holds the assistant role (the engine is ours, the role isn't required)
- `imeOptions` action keys (Go / Search / Send / Next): label and behaviour; multi-line fields; `textNoSuggestions` and `textCapSentences` / other capitalisation flags; a hardware keyboard attached
- Liveness (N-01)
- Long-press on a key with no alternates; caps lock then switching fields; double space after a number or URL (no period); learning a misspelling then removing it from the dictionary ("– word", R6 §2.2.7)
