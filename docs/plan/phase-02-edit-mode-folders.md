# Phase 02 — W10M edit mode, live folders and pin to Start

## Goal
Long-pressing a tile enters W10M edit mode (final release): move, resize (small / medium / wide) and unpin. Long-pressing an app in
the app list offers Pin to Start. Dropping a tile on another creates a live folder that expands inline. The layout persists across
process death and reboot through phase 01's layout store and follows app uninstalls, updates and disables. Phase 01's
default layout seeds Start only when no persisted layout exists. Everything extends phase 01's tile model and layout store.

## Scope
**In:** edit mode interactions and motion (values from R6 §1, see Decisions: R3 has no edit-mode row); pin from the app list; unpin; resize; move with reflow; live folders (create, add to, rename per interview, expand, remove, dissolve); persisting these through phase 01's store; LauncherApps callbacks for uninstall / update / disable; Settings page and checklist rows this part needs (if any).
**Out (explicitly):** changes to the phase 01 tile engine beyond adding what folders need; Cortana tile (03); anything for post-plan updates.

Reflow slide, candidate (LOW, R6 §1.3.2, RS2-era capture refreshing at ≈10 Hz): tiles that must make room slide, never fade or jump, over ≈300 ms with an ease-out; H4. Drag over an occupied cell (R6 §1.3.3 UNMEASURED; one rule for folder and move, replacing the earlier "reflow as soon as the centre enters" rule, which left no tile to drop on): approximation. When the dragged tile's centre enters a cell occupied by another tile, that tile holds still for a dwell of 2000 ms and shows the folder-create feedback (§1.6.1, line below); a release during the dwell creates a folder. If the centre stays over that tile for the whole dwell, the feedback clears and only then do the tiles there slide out of the way down the grid with the reflow slide; a release after that moves the dragged tile into the freed cell with no folder. Leaving the tile before the dwell ends clears the feedback with no reflow. The dwell was chosen above the ≈1.7 s hover in R6 §1.6.1 (7.83 → 9.50 s, 2015 build) that created a folder with the target held still, and is judged in H20; the reflow is judged in H5. ## Edge cases
- Pinning an app already on Start; pinning when Start is long; resizing to wide at the right edge in 2-column mode
- Changing show-more-tiles reflows a persisted layout without losing tiles
- Folder containing wide tiles; a wide tile added to a folder; a folder dropped on a folder (no nesting, H23); a folder left with one tile, by unpinning or by uninstalling one of its two apps (dissolves, H19); uninstalling an app inside a folder
- Back pressed in edit mode, with and without a folder expanded (exits edit mode; the folder stays expanded, H9)
- Drag during a live flip; process death mid-drag
- Drag across several occupied cells without stopping (no reflow, no folder feedback left behind); release exactly as the dwell ends; a wide dragged tile whose centre sits over a small tile
- Layout store written by an older shell build (upgrade keeps the layout)
- Secondary tiles: request while Start is not visible or the requester is in the background; duplicate `tileId`; owner uninstalled with its tiles inside a folder; owner update changes a tile's arguments
