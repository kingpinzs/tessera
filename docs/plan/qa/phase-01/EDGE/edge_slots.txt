## DEFECT: a role slot did not follow a role change
old build: after the SMS role changed, the Messaging row tile kept the previous holder. Start re-resolved its slots only when the layout, app list, badges or tile content changed, and a role change touches none of those.
Android gives a launcher no live signal: RoleManager's listener needs a system permission, the pre-Android-10 Secure keys read null (settings get secure sms_default_application -> null), and ACTION_DEFAULT_SMS_PACKAGE_CHANGED is sent only to the old and new default app (registered for it: no broadcast arrived).
fix: Start re-resolves its slots on resume (SlotDefaults), which is the path a user takes: change the default in Settings, come back to Start.
