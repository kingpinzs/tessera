## reading
F1 one app badging another: refused. With a sender that shares its identity the mismatch is caught ("sender is not the
badge's package"); with a sender that does not (how the real ShortcutBadger senders send) the broadcast is refused
outright, and the victim's count stayed at its notification-derived value. Turning on "Accept badge counts from
senders that do not identify themselves" accepts them again, which is the old behaviour and the user's choice.
F2 an image the caller never delivers: refused after 3 s ("did not deliver the image within 3000 ms"), the call
returned in 4 s instead of holding a binder thread.
F4 quota before writing: no image files were written for the caller after any of the refusals.
F5, F6, F7, F8: code changes with no device-visible behaviour to measure here (system-package check on the Samsung
authority, generic authority errors, one shared change URI, stored file names validated, backup turned off).
F9 master switch: with "Let apps update their tiles" off a call is refused ("the user turned live tiles off for every
app") and the caller's tile content is cleared; turning it back on accepts again.
Reinstall under a different signer: the stored state is wiped ("wipe ... package removed (tiles, queue, schedule,
badge cleared)") and the new install starts empty.
Other caps proven here: XML past 8 KB (error xml-size, 9084 chars > 8192), 14 images in one payload (error
image-count, 14 > 12), an image URI with no grant to the shell (error image-read, "no read grant").
