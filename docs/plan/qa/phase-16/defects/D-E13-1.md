# D-E13-1 — People crashes when it is opened with no Contacts permission at all; two crashes and Android drops the shell as the home app

- **Row / clause:** E13's in-place grant leg (gate review A, finding 10; product commit dcf28edc): "with Contacts not
  allowed, open People, grant from the notice; the slice holds `[app] feeds started (people grant)` …". The leg never
  reaches the notice.
- **Build:** the fifth build, `app-debug.apk` md5 `e03a1d233ee6ba0c` (commit ac4a972d). The two lines at fault date
  from the first People build (`git blame`: PeopleData.kt:39-45 at 867fcdac, PeopleApp.kt:263-267 at 776c4fb9), so
  every build of this phase has it. No earlier row met it: each one that revoked a Contacts permission revoked ONE of
  the two (E13: WRITE; EDGE P06: READ), and the provider lets an app holding either one register an observer.
- **Found by:** `E13_LEGS=grant scripts/e13.sh`, run once at 04:07–04:13 on 2026-10-02 (21 passed, 24 failed, 2
  recorded). Kept run: `qa/phase-16/E13-legs-grant-run1-on-e03a1d23-FAIL-people-crashes-with-no-contacts-permission-21-24-2/`
  (`E13.txt`, `logcat-crash-app.tileshell.txt`, `g-notice.png`, `g-notice.xml`, `g-tile-pattern.xml`). The first
  failure is the defect; the 23 after it are the same failure seen again (no notice, so no grant, no photo, no tile).

## Steps
1. `adb shell pm revoke app.tileshell android.permission.READ_CONTACTS` and the same for `WRITE_CONTACTS` (the state of
   a phone on which Contacts was never allowed; the revoke ends the shell's process and Android starts it again).
2. Start is on show, pid 31540; its slice holds `[app] feeds started (process start)` and
   `[people] tile: 0 photos (no contacts access, start)`; the PEOPLE tile shows the static pattern (all asserted, pass).
3. `adb shell am start -W -n app.tileshell/.people.PeopleActivity -a android.intent.action.MAIN`.

at 04:14:03. (No log line of Android's saying why was found in the main buffer; the page appeared after the second
crash of the home app's process within a minute.)

## What the code does (read, not changed)
`people/PeopleApp.kt:264-267` registers the provider observer whenever People composes:
`DisposableEffect(context) { val observer = PeopleData.observe(context) { … } … }`, and
`people/PeopleData.kt:43` calls `contentResolver.registerContentObserver(ContactsContract.AUTHORITY_URI, true, observer)`
with no check of either permission. The Contacts provider refuses an observer from an app that holds neither
READ_CONTACTS nor WRITE_CONTACTS (the exception's own words). The tile's feed does check first
(`feeds/PeopleFeed.kt`: `if (PeopleData.canRead(app) && observer == null)`).

## What the spec says
The cannot-read notice with the grant offered in place (`PeopleApp.kt:329`, CANNOT_READ; phase 10 E18's form) is the
page a user without the permission is meant to see; finding 10's fix (the grant made there starts the tiles'
observers) can only be reached from that page.

## What is and is not shown
- Shown: with neither Contacts permission held (as after `pm revoke` of both; the state of a phone where Contacts was
  never allowed) People cannot be opened at all, and opening it twice costs the shell its place as the home app.
- NOT shown by this run: `[app] feeds started (people grant)` itself. The leg revoked both permissions; with READ
  revoked and WRITE still held People opens on its notice (EDGE P06, `[people] list: 0 contacts read=false write=true`),
  and the driver can run the leg in that state (`E13_GRANT_REVOKE=read`) — not run; the lead's call.

## The device afterwards
The leg's own restore ran (both permissions granted, fixtures and the pushed JPEG removed, raw_contacts equal to before,
baseline layout). The home app was put back by hand at 04:14 with provision.sh's own command,
`adb shell cmd package set-home-activity app.tileshell/app.tileshell.StartActivity` (Success); after it the Home
intent resolves to `app.tileshell/.StartActivity` and Start is the resumed activity.

## Fix and re-run (2026-10-02 04:19–04:22)
Fixed in product commit e226bc68 (`people/PeopleApp.kt`, `people/PeopleData.kt`): the provider observer is registered
only once READ_CONTACTS or WRITE_CONTACTS is held, again when a grant changes that, and a refused registration is
logged (`[people] observer not registered: <kind>`), not thrown on.
Re-run once on the sixth build, `app-debug.apk` md5 `585b457ffc29878c` (commit e226bc68): `E13_LEGS=grant
scripts/e13.sh` with both permissions revoked (the default) — **49 passed, 0 failed, 4 recorded**, kept as
`qa/phase-16/E13-legs-grant-on-585b457f-49-0-4/` (driver `e13.sh` blob f096c31b).
- People opens on its notice: `people_notice` reads "People can't read your contacts. Allow Contacts to see them here.",
  `people_notice_action` reads "allow access"; People is the activity on show.
- No crash: the shell's entries in Android's crash drop box number 2 before People is opened (this defect's two, from
