## Steps
1. Tessera exists, no fixture calendar. Open Tess (`KEYCODE_ASSIST`), type `add a calendar event called dentist tomorrow at 2 pm`, Enter.
2. The confirm card shows. Tap `cortana_card_button:confirm`.
3. `content query --uri content://com.android.calendar/events --projection _id:calendar_id:title:dtstart`.

## What the product does
- The card's fields (dump `A-card.xml`): `Add this to your calendar? | Event | a calendar event called dentist | 2:00 PM | Tomorrow`.
- The reply is "Added to your calendar." and the row written is
  `_id=759, calendar_id=1, title=a calendar event called dentist, dtstart=1790971200000` (Tessera, tomorrow 14:00 — the
  calendar and the time are right).
- `title='dentist'` matches no row (`events: No result found.` in `E9.txt`).
- Tess's read then says: "You have E9 checkup and a calendar event called dentist."

## What the spec says
The event is "dentist": `events` lists "dentist", the Calendar app's day view lists the same event, and "delete the event
dentist" deletes it.

## Diagnosis (one line; read, not changed)
`cortana/match/CommandMatcher.kt:189` strips `\ban? (appointment|meeting|event)( (called|named|for))?\b`, which matches
"a meeting called" and "an event called" but not "a **calendar** event called" — and line 188's `my calendar` strip does
not touch "calendar" either — so the whole phrase stays in the title. Phase 03's own rows used "add a meeting called
standup …", which the rule covers; phase 16's E9 is the first row to type this wording.
