## What the fix build changes for the rows (the row writers are told when it is installed)
- `calendar_sync.json`: every calendar key carries `"name"`; a file written by hand without it allows nothing.
- New or changed ring lines: `open other -> …` (an unhandled action); `[people] pick: no caller to return a result to; the list was opened`, `pick: cancelled`; `[calendar] reminder: n skipped (due before the shell's first start)`; `reminders count from <ms> (…)`; `swipe ignored (no such alert now)`; `reminder poke failed: …`; `calendar_sync.json: allowed: n of m entries dropped (…)`; an unreadable store is kept as `calendar_sync.json.unreadable-<ms>`; Sync outcome `failed the copy could not be read`.
- PICK started with `am start` (no caller) opens the plain list.
- Calendar classes on `phase-16-cal`: unit suite 1199 / 0 (`dev-cal/unit-F20.out`); People's on `phase-16-people`: 1172 / 0.
- The editor's rule between "+ Phone" and "+ Email" is gone when neither kind has a field (F31); a new contact's draft still shows it (it starts with one empty box of each kind).
- `[people] link <a>+<b>: refused (not allowed)` is a third Link / Unlink outcome (F23's ruling, 05ae0b23).
