## L13-18 (checked, holds)

1. **Where About can be opened from.** The "…" menu is composed only on the tabs and the two editors: ClockApp passes
   `menu` to TabsScreen, AlarmEditorScreen and TimerEditorScreen. About, Sounds, MusicPicker and the two expanded pages
   have no app bar. So `aboutFrom` is always Tabs, AlarmEditor or TimerEditor. It is never About, so Back cannot loop.
2. **Nothing else writes `page = About`,** so `aboutFrom` is always fresh when `back()` reads it. An external open while
   About is up (a `page` extra, a tile, a notification, the AlarmClock API) goes through `show()` and leaves About; the
   API also opens an editor with its own draft. The stale `aboutFrom` it leaves behind is overwritten by the next
   `openAbout()` before anything reads it. A launcher re-open (singleTask, no extras) routes nothing: About stays, and
   Back returns correctly.
3. **Where ClockNav lives.** It is a plain activity field and is not saved. The manifest locks portrait and handles
   density, fontScale, screen size, orientation and uiMode. A locale change or process death rebuilds ClockNav at Tabs,
   with `aboutFrom` at Tabs too, so the two stay consistent. That the draft is lost on a rebuild is pre-existing.
4. **The draft while About is up.** Only the editor's Save and Delete clear `alarmDraft` or `timerDraft`, and the API
   open replaces them. Neither Save nor Delete can be reached from About. If a draft were ever null, the editor sends
   the page to Tabs, so it would not loop. `timerDraftOriginal` stays in ClockNav, so Save's dimming is right on return.
   A ring or dismiss meanwhile changes only the store; Save overlays only the draft's fields on the store's copy, the
   same as when the editor itself stays open that long.
5. **A plain `var` is enough.** `aboutFrom` is read only in `back()` on the main thread, and never in composition.
6. **Scope.** The one shared menu entry now calls `openAbout()`, which covers all three pages. Every other page's
   Back is unchanged: TimerExpanded, StopwatchExpanded and the editors still go to Tabs, and Sounds and MusicPicker to
   the alarm editor.

## L13-19 (checked, holds)

1. **It is the right producer.** Only the "…" button's `onExpand(!expanded)` writes `barExpanded = true`; the scrim,
   the menu items, the buttons and `back()` only close it. The alarm editor always opens with the bar collapsed:
   L13-17 collapses it on Add, the scrim covers the rows, the API's `show()` calls `leaveTabModes`, and `openAbout()`
   collapses it. The flyout is local state of the same composable, so closing it when the menu opens covers every way
   the menu opens. Closing the menu leaves flyouts alone, correctly: none can be open then.
2. **It is the same as a tap outside.** Days, sound and snooze are written to the draft when picked. Closing the flyout
   is therefore its scrim's `onDismiss` and loses nothing.
3. **L13-9's flyout Back.** Before the fix, Back with the menu up went to the editor's BackHandler, which is registered
   after the activity's callback and so outranks it. That Back closed the flyout and left the menu. Now the flyout is
   already closed and the handler is disabled, so Back reaches `nav.back()` and closes the menu. The handler's
   `enabled` updates on recomposition. A Back in the same frame as the "…" tap is swallowed harmlessly: the flyout is
   already null.
4. **Nothing else in the editors is left under the menu.** The timer editor has no flyouts, and the spinners draw no
   overlay. For the name field, see note 1.

## Notes (none blocking)

1. **Pre-existing, the same Back-order shape, outside L13-19's scope (both editors): the name field.**
   - Tap the name, then Back. The IME's Back hides the keyboard, but `editingName` stays true.
   - "…" then opens the menu over the live field, and nothing closes the edit.
   - Back ends the edit (the editor's BackHandler outranks the activity callback, where the bar's close lives) and
     leaves the menu up. A second Back is needed.
   - Code reading only. Worth logging as its own row.
2. **A frame window when the menu opens (this fix adds nothing in kind).** Both writes are plain.
   - The flyout's OverlayLayer unplaces it at the next layout pass, which Compose runs before hit-testing any touch.
     The menu's scrim appears only after recomposition.
   - So a new touch landing in the sub-frame window after the "…" tap reaches the editor's rows, not the flyout's
     scrim. Every "…" open already has this window.
   - Also edge-triggered: a second finger whose down came before the scrim can still open a flyout under the menu.
     L13-13's LaunchedEffect has the same edge. Contrived.
3. **"Never About" rests on reachability, not structure.** `openAbout()` does not guard `page != About`. It cannot
   loop today: the menu is not composed on About, and a second pick would need a full tap within one frame. A one-line
   guard would make it structural. Optional.
4. **Coverage gaps in the drivers.**
   - l13_18 (b) makes no edit in the timer editor, so the timer draft being kept rests on code alone.
   - No case presses Back again from a returned editor (it should reach the tabs, not About).
   - No case covers an external open while About is up.
   - l13_19 never presses Back while the menu is up after the close (the L13-9 interaction), and never picks About with
     a flyout open.
