## Agent calls, recorded now (Jeremy can overrule any)

- **Blur is a device capability, and the fallback is W10M's own colour.** Cross-window blur (the only way
  an overlay can blur what is behind it) is enabled on this AVD (testability review: supports_background_blur=1,
  mBlurEnabled=true) and unknown on the S25U / One UI 8. R4's phone list gains the probe:
  `getprop ro.surface_flinger.supports_background_blur`, `dumpsys window | grep mBlurEnabled`, both again under
  power saving, and a FLAG_BLUR_BEHIND probe overlay. Where blur is unavailable the surface draws the MEASURED
  solid W10M fill — so there is one permanent form (Rule 16), and its fallback is the original, not a v1.
- **The setup wizard shows only while a core grant is missing.** A phone that already holds every grant never
  sees it — which is also why no existing driver needs a test-only bypass: the harness provisions every grant.
  It walks the Setup checklist's own rows in order (one source of truth), then the accent.
- **The pod bay is a pager page left of Start, reached by swiping right on Start, never an edge swipe** — the
  left edge is Android's Back gesture under gesture navigation. Back from the pod bay returns to Start, as it
  does from the app list. Drivers that swipe to reach Start get a harness note in the pod-bay phase doc.
- **The shell's own apps take their slots once, following phase 10 Q5's Music precedent** (assignSlotOnce, never
  over a user's explicit choice), and Tess's alarm / camera / photo actions target the shell's app when it holds
  the slot. This re-cuts phase 01 E4 and phase 03 E2 / E10 in the phases that add those apps.
- **R11 — a measurement pass for the inbox apps** (RV9 / Q10: every value measured or a tagged approximation),
  one section per app, gating each app phase's FINAL. The pod bay and the quick actions have no W10M original:
  their values are P4 or Jeremy's own (the spring's dampingRatio 0.65), and their rows say so.
- **Order** (both reviewers converge): quick actions → setup wizard → in-app Fluent engine (before phase 04, so
  04 builds on it) → pod bay → inbox apps in groups, each gated by its R11 section → Files → the Settings front
  after phase 04 (its toggles need 04's helper). Quick actions change shipped phase 02, the wizard and pod bay
  change phase 01's fresh-start and pivot, so they go first; the apps only add.
- **Carried from R10, not re-asked:** a Tessera bar over every app waits on phase 04's R4 nav-bar probe (P5);
  a local-network LLM is not raised — Q2 and A11 stand, and Jeremy reaffirmed A11 today.
