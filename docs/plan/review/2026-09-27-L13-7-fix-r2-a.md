## Verdict: PASS

A1 is resolved at the producer. Start's comeback is now one routine: auto-size, then the recent row, then the entrance.
`onResume` and the focus return both call it. The rework is a pure extraction: `onResume` behaves exactly as it did on
every resume, and the focus path now does everything `onResume` does on a launch's return. I found no regression.

## Blocking findings

None.

## Notes (non-blocking)

- **A1, code.** `onWindowFocusChanged` (StartActivity.kt:458–461) calls `comeBack` only when `hasFocus &&
  returningFromLaunch`. `comeBack` (:467–484) runs `applyAutoSize`, consumes `pendingRecent`, and then plays the entrance
  and clears the flag. All three of A1's failure scenarios are closed. The stale promotion on the next Home, the stale
  resize, and the promotion lost to a second tap each depended on `pendingRecent` or the new scores outliving the focus
  comeback. Neither can now.
- **A1, evidence.** On d74b02ac, `back-slice.txt` shows `session hidden` at wall …259271, then `last open app:
  shell:cortana promoted` and `start entrance (focus back)` in the same millisecond (…259306). `back-1.xml` has the Tess
  tile at `[9,1579]`, and it stays there in every later dump. On 7f00cb9e, the same row reproduces A1 exactly: no
  promotion after Back (`back-1` at `[9,1151]`), then the stale promotion lands at the next `show_start` Home, on a
  visible Start (`drawn-back-0` at `[9,1579]`). The row fails there on the 4 recent-row checks and on nothing else, so
  it can now catch the defect.
- **Every onResume, not just launches.** The statement order matches 54ecf613's `onResume`: inFront,
  `setStartVisible`, `hideSystemBars`, `SlotDefaults.refresh`, auto-size (unconditional, as before), `pendingRecent` if
  set, then the entrance if the flag is set, with the same `start entrance` line. A plain resume (screen on, Home on
  Start) does exactly what it did. The control confirms it: `ctl-slice.txt` has the Settings promotion, then
  `start entrance`, in the same millisecond. `L13_4-d74b02ac` (Back and Home collectors) is 22/0.
- **Focus traffic that is not a return.** The flag gates the focus path, so the shade, dialogs and other focus changes
  do nothing, as in round 1. The focus path now also runs auto-size, but only under that gate.
- **Both callers, either order.** If focus ever arrives before `onResume` on an ordinary launch, `comeBack` runs twice.
  The second run is harmless. `LayoutStore.mutate` returns early when nothing changed (LayoutStore.kt:260–265), and
  `RecentApp.opened` returns early for the same key. `pendingRecent` and the flag are already consumed, so there is one
  entrance. This also closes round 1's ordering note, where the entrance could start before the promotion.
- **Timing of the layout writes.** On the focus path, Start is still on its exit's last frame (tiles off screen) when
  `comeBack` runs. The layout writes and `animation = StartAnimation(entranceElapsedMs = 0f)` happen in the same
  main-thread callback, the same shape as `onResume`. The comment "while the tiles are still off screen" holds for every
  launch return.
- **Tess's brief-focus paths** (the step-aside `setUiEnabled(false)` and the microphone `hide()`, each before the page
  pauses Start). When Start gets focus for a moment, the promotion and auto-size now land there, under entrance frame 0,
  instead of at the later `onResume` with no entrance, as on 54ecf613. That is an improvement. The missed entrance on
  the return from that page is unchanged from round 1: Start comes back fully drawn, never black.
- **The drawn Windows key in Tess.** `drawn-windows-slice.txt` (d74b02ac) shows `onResume`'s `start entrance`, then
  `session hidden` 1 ms later, and no second entrance. The tile was already promoted, so there is no promotion line.
  This is unchanged in kind.
- **Failed launches and a stale flag.** A tile launch that silently fails (secondary tile false, shell tile with no
  target, a session that never shows) leaves Start on the exit's last frame. The next focus return now also applies the
  sizes and the recent row there, with the tiles off screen, before the entrance. That is consistent, not a new risk. The
  app-list launch (StartActivity.kt:231) passes `key = null`, so it never sets `pendingRecent`.
- **Auto-size is proved by code, not by device.** The Tess tile is 343 px square in every dump on both builds, so no
  size threshold was crossed and the row cannot see auto-size's timing. It shares `comeBack` with the promotion, which
  the row does see, and it runs first there. Optional: add a check that the Tess tile's size at `back-1` equals its size
  at `drawn-back-0`.
- **Outside L13-7 (a possible ledger item, not this row).** The scores decay slowly over time (`use shell:cortana ->
  18.235462 / 19.235313 / 20.235132`, a little under +1 per tap). `onResume`'s auto-size is unconditional, so a Home
  press on a visible Start could in principle cross a size threshold on decay alone. This is my inference, it is older
  than L13-7, and round 1 said to leave the unconditional auto-size alone.

  d74b02ac (installed 2fbe728b) is bf20237a's tree rests on the README. `git diff bf20237a HEAD -- app/` is empty. The
  7f00cb9e run's header reads `built d74b02ac`, `installed c519a4db`, `match NO`. The installed hash is the one the README
