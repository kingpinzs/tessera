## The defect (phase 10's part: music/)

Three overlays close on Back only by writing their state, and stay hit-testable until they leave the composition a
frame later. A touch in that frame lands on the stale full-screen scrim and is lost:
- Music's hold menu (`MusicMenu` from `MusicCollectionPage`, `menu = null`);
- Now Playing's "•••" menu (`MusicMenu` from `NowPlayingPage`, `more = null`);
- the playlist name box (`PlaylistNameBox`, `naming = null`).

Reproduced with `qa/phase-13/scripts/l13_6_probe.sh` before the fix: `qa/phase-13/L13-6-repro-707aa55b/`.

## Fix

- Each of the three is drawn in `OverlayLayer` (ui/components/ModalOverlay.kt, L13-3). The layer places it only while it
  is open, so the layout pass that Compose runs before each touch's hit test takes a dismissed overlay out at once.
- Their Back writes go through `dismissOverlay`, which applies the write at once:
  - Music's page `BackHandler` and its drawn Back (the naming and menu branches);
  - Now Playing's `BackHandler`.
- `MusicMenu`'s items end on `waitForUpOrCancellation`, which returns null for the consumed up of a removal, so an item
  under a held finger does not run (no L13-5 counterpart).
