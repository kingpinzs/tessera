## Root cause (traced on the AVD, 2026-09-30 12:32, whole device log)

Evidence: `qa/phase-14/L14-1/rootcause-run1/` (driver `qa/phase-14/L14-1/rootcause-probe.sh`; `logcat-all.txt` is
system_server + SystemUI, `app-ring.txt` is the launcher's ring). Four defects stack:

1. **The unlock page cancels its own unlock.** `CortanaUnlockActivity` is `showWhenLocked` (manifest + `setShowWhenLocked(true)`)
   and calls `requestDismissKeyguard` in `onCreate`. SystemUI accepts it and starts the PIN pad (`logcat-all.txt:82`
   "Show primary bouncer requested", `:97` LOCKSCREEN → PRIMARY_BOUNCER). 73 ms later the page's own launch finishes as a
   *keyguard occlude* transition (`:119`); SystemUI's occlusion handling resets the keyguard and cancels every pending
   dismiss (`:127` `setOccluded(true)`, `:135` `DismissCallbackRegistry: notifyDismissCancelled(1)`, `:137` bouncer
   hiding). Showing over the lock screen is exactly what makes it occlude.
2. **Tess's window sits above the PIN pad.** The session window is `TYPE_VOICE_INTERACTION`, which layers above the
   notification shade that holds the keyguard and its PIN pad; a PIN pad raised under a shown Tess cannot be seen or used.
3. **The session is hidden and the request dropped.** On the cancel the page finishes; the keyguard un-occludes
   (`:205` unocclude transition) and ~100 ms later the session hides (`app-ring.txt`: `session hidden` at .720; nothing
   in the shell asked for it). `onHide` → `CortanaModel.stop()` resets the state — the pending request goes (H12's
   "closing the session drops it", working as ruled; the hide itself is the defect's consequence). The user is left on
   the lock screen, not the PIN pad.
4. **The tap drops the card and re-speaks.** `ActionLayer.confirm(Pending.Locked)` returns
   `Outcome("Unlock your phone to continue.", null, pending = pending)` — card `null`, so the card leaves the screen on
   the tap, and the line is said a second time. Phase 03's Decision ("a cancelled unlock does nothing at all — the card
   is still there and the request is still pending", also `CortanaUnlockActivity`'s KDoc) cannot hold, and phase 14 E8's
   "`reply_since` MARK2 is the doors line" reads the re-spoken line first (E8 run 3: got "Unlock your phone to
   continue.").
