## Findings

### BLOCKING

**B1 — product defect: a cancelled build is cached as a failed build, so the app list can stick in the fallback while acrylic is
on.** `app/src/main/kotlin/app/tileshell/ui/fluent/StaticBackdrop.kt`. `render` runs in `withContext(Dispatchers.IO)` (`:99`)
inside `decoded.mapCatching { … }` (`:75`). `mapCatching` catches every Throwable, including the CancellationException `withContext`
throws when the calling LaunchedEffect is cancelled mid-render. `onFailure` (`:84-87`) then stores `Layer.Failed(key)` and writes
`[fluent] static backdrop failed for <uri>: …CancellationException… (fallback)`. Since 3448c92f the effect is keyed on `state.on`
(`:181`). So if acrylic goes on and then off inside one build window, the new effect's `drop()` (`:183`) runs on the next frame, and
the cancelled coroutine writes `Failed(key)` after it when the render returns. `Key` does not include `state.on`. The next on
therefore calls `ensure` with the same key and returns at `:72` without building, and `acrylic = state.on && built != null` (`:193`)
stays false. The app list draws the unblurred fallback under `[fluent] acrylic=on reason=none`, with a false failure line, until
the next off / on, a picture change or a restart. The window is the measured build time, 52–144 ms (`E1/slice-5-switch-on.txt`,
`slice-3-saver-off.txt`, `slice-1-start.txt`; 69 ms in `E10/slice-C.txt`), and the build runs while Settings is in front (the same
slices). A quick double tap on the switch followed by another tap reaches it; so do phase 12's preset taps and a battery-saver
flick. The QHD+ phone builds slower, so its window is wider. No capture shows it, because no row flips the state twice inside
150 ms; it is found by reading the code. It breaks the on / off rule (acrylic on, fallback drawn). It also breaks the diagnostics
contract: the failed line is reserved for "file gone, decode failure, grant revoked" (doc :180-181, T13-10). Fix at the producer:
in `ensure`, rethrow CancellationException instead of recording it, so only a real failure becomes `Failed`. Re-verify with a probe
that taps `theme_transparency_effects` twice about 60 ms apart in one `adb shell`, then again 2 s later, and asserts no
`static backdrop failed` line, a rebuilt line and E1's blurred edge spread; then re-run E1, E10 and E13.

**B2 — a written Decision and build task unmet: no INDEX Change Log line records phase 13's ADDs to FINAL parts.** Build task 7
(`docs/plan/phase-13-fluent-materials.md:313-315`) requires "INDEX Change Log lines for phases 01 (app-list backdrop form, the
`BackgroundDecoder`), 02, 03 and 10 (their surfaces now acrylic, numbers unchanged; the `[motion]` lines) and 11 (satellites draw the
two lights; the press point in `EditGestures`, T13-25) when built". The fallback Decision (`:120-121`) promises the phase 01 line
(H3). The INDEX has none: the phase 13 lines (`INDEX.md:90-105`) cover blocks, re-cuts and QA, and rows 01 / 02 / 03 / 10 / 11 name
phase 13 only for L13-1 / L13-2. These changed without a line:
- `start/StartPage.kt:1146-1147`, the decode moved to `BackgroundDecoder`.
- The app list now draws the Start picture (phase 01's visible form).

- `StartActivity.kt` gained `[motion] pivot`.

The precedent is `INDEX.md:126` (phase 11) and `:133` (phase 15). Jeremy's end-of-project whole-gate run needs these lines to

### NON-BLOCKING

- **N1 — the picture is decoded up to three times at once.** `start/BackgroundDecoder.kt:26-44` has no in-flight dedup. On a
  picture change or at process start, `StartPage.kt:1146-1147`, `StaticBackdrop.kt:176` and `ensure` (`:74`) start in the same frames
  and each decodes. That is transiently 2–3 × the decode: 3 × 64 MB for EDGE_HUGE's 8000², sampled to 4000². The KDoc's "decoded once
  per process and URI" (`:12-14`) is false under overlap. E10 and EDGE_HUGE measure only the settled state.
- **N2 — the static layer is a software copy (`StaticBackdrop.kt:139-140`), so on a real GPU it costs the bitmap plus its uploaded
  texture.** At QHD+ that is ≈ 2 × 17 MB against P2's "+ 30 MB". The AVD reports Graphics 0 (`E10_DIAG/E10_DIAG.txt`), so E10 cannot
  see it. Keeping the hardware bitmap would halve it. This is projected, not measured; P2 decides.
- **N3 (phase 04) — the noise clamp biases a black surface's mean by ≈ +1.4 levels.** `FluentEffects.kt:30-31` clamps the ±5 noise
  at 0: `E4/E4.txt:61` reads (1.5,1.5,1.5) against (0,0,0). That is inside this phase's ±4, but phase 04's black action center /
  volume panel colour rows, re-specified from this table, will trip at ±1 unless they read patch means with ≥ 2 tolerance.
- **N4 (phase 14) — the pod bay can evict the app list's layer.** `StaticBackdrop` is one singleton layer keyed by (uri, size,
  tint, radius) (`:57-66`), and `AppListBackdrop` hardcodes `FluentSurface.APPLIST` for its tag and lines (`:189`, `:198`, `:201`).
  The pod bay must share the identical key (same page size, same tint), or it evicts the app list's layer. The evicted page then
  draws the fallback silently, because its LaunchedEffect keys do not change (`:192`).
- **N5 (phase 04) — `Fluent.state` reads (on, none) before `Fluent.start`.** It starts that way (`Fluent.kt:155`), and start runs in
  `startLauncher`, which waits for the first unlock in direct boot (`ShellApp.kt:45-55`, `:68`). An overlay drawn before the first
  unlock would draw acrylic whatever battery saver says.
- **N6 — stale doc sentences on the live source.** The doc says the live source "records only while its surface shows" and
  "allocates its layer only while a surface shows" (doc :100-101, :188-189). Under T13-11 as built, every page with a live surface
  records itself into L on every draw (`LiveAcrylic.kt:61-66`; `AppListPage.kt:285`, `RemindersPage.kt:353`,
  `CortanaSessionRoot.kt:90`, `MusicCollectionPage.kt:213`, `MusicNowPlaying.kt:219`). L has no effect, so it has no offscreen buffer;
  only S is surface-lifetime. The doc sentences are stale; a Change Log clarification is enough.
- **N7 — phase 03's row is stale.** Row 03 still says "E15 and the edge cases NOT RUN" (`INDEX.md:51`), but E15 has run twice
  (21/6 on db078d6a). Its six failures and the `e15.sh` `grep -c` fault are recorded only in phase 13's lines (`INDEX.md:90`, `:95`),
  where phase 03's end-of-build pass will not look.
- **N8 — the lights ignore consumption.** They end only at up, cancel or leaving bounds (`RevealLights.kt:80-87`), not when another
  handler consumes the move, unlike the Compose press semantics T13-13 cites. No surface in this phase scrolls under a held item, so
  nothing can see it here; it matters for a later scrollable transient surface.
- **N9 — turning acrylic on shows one build of fallback first.** The app list draws the fallback for ~50–144 ms before the blurred
  form (above). This is acceptable, but record it with B1's fix, since T13-15's "no unblurred frame shows" now holds only for
  process start.
- **N10 — T13-18 was never recorded as its own result.** Its build-start check (static route width = on-screen layer width) has no
  result line of its own. The evidence carries it (`E2/E2.txt:19` 130.2 px static, `E3/E3.txt:40` 133.3 px live, `E3/E3.txt:39`
  oracle match).
