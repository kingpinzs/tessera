## Round 1's blocking finding is resolved
- The new root handler is `pointerInput(Unit) { awaitEachGesture { awaitFirstDown(requireUnconsumed = false) } }`
  (`clock/WorldClockTab.kt:235`). In foundation 1.11.4, `awaitFirstDown`, `awaitEachGesture` and `awaitAllPointersUp`
  make no `consume` call. The handler is an ancestor of the field and the results, so it runs after them in Main and
  changes nothing they see in Main or Final.
- So the result rows' `PressBox` Final-pass check, `CoreTextField`'s tap, cursor and long-press selection, and the
  results' `ScrollableNode` all get exactly what they got on 05e543d7.
- The only other handler above the search is the pager's `detectHorizontalDragGestures` (`ClockTabs.kt:265`).
  `ClockScaffold` has none. A horizontal drag on the search therefore reaches the pager unconsumed, as it did on 05e543d7.
- Row case (4) tests a moving tap and a drag on the results. bd114d21 fails it; ce79bc17 passes it 25/0. The field's
  tap and selection and a tab swipe over the search rest on code reading.

## The blank parts still do not reach the city list (ui-android 1.11.4)
- `InnerNodeCoordinator.hitTestChild` walks `zSortedChildren` from the top. After each placed child, it stops unless
  `!hasHit()` or that child's `outerCoordinator.shouldSharePointerInputWithSiblings()`. Both branches of
  `ComposeUiFlags.isSkipNonImportantSemanticsNodesHitTestEnabled` (true by default) come down to this rule for
  pointer input (`PointerInputSource.shareWithSiblings`).
- At WorldClockTab's Box, that child is the search's `OverlayLayer` (`:167`), which is last in z-order. Its modifier
  chain is empty, so there is no PointerInput head and sharing is false.
- A down inside the page reaches the root node: `NodeCoordinator.hitTest`, then `isPointerInBounds`, then
  `HitTestResult.hit`. That records distance -1, in layer and not in expanded bounds, so `hasHit()` is true.
- Consumption plays no part in hit testing. `clock_list` (`:137`) is never in that pointer's hit path for the whole
  gesture, so `CityRow`'s hold cannot fire. A vertical drag on a blank part also no longer scrolls the hidden list.
- This covers every blank part: the gaps around the field and the "No results" page (case 2). Where the results list
  exists, its own scrollable node was already a hit on 05e543d7.
- The pattern is the same one `ClockFlyout`'s scrim already uses (`ClockWidgets.kt:215`).
