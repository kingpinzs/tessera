## `untilInterrupted` (StartActivity.kt:400-407) against MutatorMutex (foundation 1.11.4)

| Step | Bytecode | Consequence |
|---|---|---|
| `pager.animateScrollToPage` | calls `PagerState.scroll`, then `awaitScrollDependencies`, then `scrollableState.scroll` (no catch). | The interruption reaches the caller unchanged. |
| `DefaultScrollableState.scroll` | calls `coroutineScope { scrollMutex.mutateWith(...) }` | adds one scope coroutine |
| `MutatorMutex.mutateWith` | runs `coroutineScope { Mutator(priority, coroutineContext[Job]) }`; `$mutateWith$2` reads `Job.Key` from the **scope's** context | The mutator's job is the inner scope, not the collector. |
| Interruption | `Mutator.cancel` = `job.cancel(MutationInterruptedException())`, a `PlatformOptimizedCancellationException`; a lower priority throws `CancellationException("Current mutation had a higher priority")` from `tryMutateOrCancel` | Both are `CancellationException`s, so the `catch` sees both. |
| Parent untouched | coroutines 1.9.0: `ScopeCoroutine.isScopedCoroutine` returns true, so `JobSupport.cancelParent` returns early | The `LaunchedEffect` job stays active. |
| `currentCoroutineContext().ensureActive()` | `get(Job)?.ensureActive()` | An interruption returns false. The effect's own cancellation (`LeftCompositionCancellationException` on teardown, or cancellation during `awaitScrollDependencies`) throws. |

`scroll.animateScrollTo(0)` (Home) goes through `ScrollState.scroll` → `DefaultScrollableState.scroll`, the same path.
The one case the old code also lost, a Back or Home while a finger is dragging the pager, is now caught
(`UserInput` > `Default`, so it is rejected up front). The collector lives.

## Key order and lifecycle

- **Key order.** The collectors are ee4bf960's, line for line, except that the pivot is wrapped (compare
  `git show b2d44b7d~1:…/StartActivity.kt`). Every sequence without an interruption runs as it did before L13-4. In
  particular, a second Back during the pivot waits in `extraBufferCapacity = 1` and runs as `backOnStart()`. Every
  sequence with an interruption used to kill the collector, so there is no ordering to regress.
  - Home and Back interrupting each other's pivot through the shared mutex is the pre-L13-4 behaviour. Home loses its
    scroll to the top in that case.
  - `twice` pins the order. It needs a `[back]` line, which `BackHistory.findTarget` always writes (`start/BackHistory.kt:31,59`),
    and no `interrupted` line. The d6a364c8 slice shows `back: pivot interrupted by a touch` with no touch; the 00244cec
    slice shows the `[back]` line and a launch.
- **Lifecycle.** The effect is cancelled only when `StartHost` leaves composition, and `ensureActive` rethrows there.
  A pivot in flight at ON_STOP waits on Compose's paused frame clock and ends after ON_START, as at ee4bf960. A Home
  that arrives meanwhile is buffered, as before.
- **Mutation.** Without the `catch`, the L13-4 row goes red. With the child `launch` back, `twice` goes red. Without
  `ensureActive`, the collector swallows its own teardown and writes one stray log line. No test sees that, and it
  does no harm.
