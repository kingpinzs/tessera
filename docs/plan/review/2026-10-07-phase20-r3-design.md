## BLOCKING

**D1 — Station/server items cannot be built "beside `MusicService.mediaItem`" or "inside the existing `onSetMediaItems`, no new override" (L360-362, L384-390, T20-2).**
`app/src/test/.../media/UriAccessWiringScanTest.kt:326-343` pins the service source: `onSetMediaItems` must equal `setItemsForm`, `count(service, ".setUri(") != 2` fails, `count(service,"setMediaItems(") != 1` fails, `MusicQueueStart.*` exactly 3 calls. `MusicSearch.Match.queue` is `List<Track>` (`music/MusicSearch.kt:18`). The search branch (`MusicService.kt:187-196`) runs for ANY uid, so a stranger's `playFromSearch("x radio")` would start a network stream.
What does survive: the shell's own controller keeps URI items (`MusicItemRule.kt:47`), and a favourites queue set by `MusicPlayer` passes `MusicQueueStart.set` (all counts 1).
Fix, replace task 3's first clause and task 7's "no new override":
> Station and server items are built ONLY in `music/radio/StationItem.kt` and `music/server/ServerTrackItem.kt` (media ids `station:<uuid>` / `server:<id>`, never a decimal, so `MusicItemRule.libraryId` cannot match), each after its URL rule accepts. Taps set them through the shell's own controller (`MusicPlayer.playStations`), which `MusicItemRule` keeps. `MusicSearch.resolve` gains a `stations` argument and `Match` a station form; the session passes stations ONLY when `controller.uid == Process.myUid()` (pure `RadioSearchRule.stationsFor(controllerUid, myUid)`); a stranger's search stays library-only. `UriAccessWiringScanTest`'s `setItemsForm` and `.setUri(` clauses are rewritten in the same commit, with a new clause that the two builders are the only other `.setUri(` under `music/`; that diff is part of the adversarial review. Resumption stays unanswered: after process death no station queue returns.

**D2 — `artworkUri` = the directory's `favicon` defeats T20-5 (L361, L235).**
Media3's session loads `artworkUri` itself for the notification/platform metadata (`MusicFeed.kt:200` reads that bitmap). From Media3 source as I recall it (verify in `r11/src`): the default `DataSourceBitmapLoader` uses `DefaultDataSource` (file/content/asset/http) and reads to end, uncapped. Addendum §1: favicon is `http://` on 159 of the top 2,000.
Fix: "A station item NEVER sets `artworkUri`. The logo is fetched by the shell (http/https only via `StationUrl.accept`, ≤ 512 KiB, decoded at bounds ≤ 512 px like `MusicService.boundedArt`) and set as `artworkData`. Logos are fetched only for favourites and the playing station; browse rows draw the placeholder (no fan-out to thousands of hosts)."

**D4 — Jellyfin music has no listing and no token path; the lead's §7.11 is incomplete.**

The store is cross-process by design (`net/CredentialStore.kt:26-29`).
Wording for §7.11 (replaces L262-264, L399-400):
> Server tracks play `<base>/Audio/<id>/stream?static=true` with NO token (Jellyfin 12.1: no `[Authorize]`), so the shared player carries no credential and radio hosts can never receive one. Listing uses the `Authorization` header as built. If the fixture answers 401 at build start, the fallback is phase 17's own route and nothing else: `STREAM_PATH` becomes `/(Videos|Audio)/…/stream` and `MusicService`'s data source is wrapped in `ResolvingDataSource(MediaServer.streamResolver)` (already same-server-scoped by `mayCarryToken`). URLs are logged through `ServerRules.withoutQuery` either way.
ADDs: `ServerRules.musicPath(userId)` (`includeItemTypes=Audio&fields=…`), `parseTracks` (Album, AlbumArtist, IndexNumber, `RunTimeTicks/10_000` → `durationMs`), `audioStreamUrl`; `MediaServer.music()`; a `tag` constructor argument (default `"video"`).

**D5 — The directory is not one cacheable fetch (§7.3; L163-172, L375, P10) and the mirror rule has no name source (§7.5).** Replace with:
> **Fetched** (explicit limits, `hidebroken=true`): `/json/stations/topclick/2000` (2.4 MB), `/json/tags?order=stationcount&reverse=true&limit=500`, `/json/countries`. **Cached** (`AtomicFile`, `radio_directory_v1.json`): 11 slim fields per station (~0.8 MB), the 500 tags, the countries; video-codec rows dropped at parse. **Caps:** any directory response over 4 MiB → `radio: directory too large`, cache kept; cache file ≤ 2 MiB. **Offline, and Tess always (P6):** search / genre / country run over the cached 2,000 plus favourites. **Online, in the app only:** search, genre and country also ask `/json/stations/search?…&limit=100&order=clickcount&reverse=true`, shown after the cached hits, not cached. **Favourites** (`radio_favourites.json`, ≤ 200) store the full slim row plus `lastPlayedWall`; refreshed by uuid on directory refresh (`/json/stations/byuuid`). **Refresh:** on opening the radio pivot when the cache is older than 24 h, and on demand. **Mirror:** `InetAddress.getAllByName("all.api.radio-browser.info")` → each address's canonical host name → pure `RadioMirrors.order(names, seed)` keeps only names ending `.api.radio-browser.info` (inside the https-only domain-config; `EndpointLiteralScanTest.kt:121` accepts subdomains), dedupes, shuffles, tries each in turn; an empty list → `all.api.radio-browser.info`. **Click:** `GET /json/url/<uuid>` on each user-initiated start (tap, next/previous, Tess), never on a reconnect.
All through `VideoHttp.get(url, headers, maxBytes)` (`video/catalogue/Catalogue.kt:63`: capped, logs no URL), not a new `HttpURLConnection` path. P10: n ≥ 1500.

**D6 — Stations "ahead of the library" steals phase 03's ruled "play <song>"; "play radio" is undefined in three cases (L132-133, L387-389).**
`CommandMatcher.kt:91-93` already maps every "play <rest>" to `PlayMusic(rest)`, so station phrases need NO matcher ADD. But `ActionLayer.kt:584-594` resolves against the library itself and replies "I couldn't find…" before the session is asked, and its no-controller branch calls `MusicPlayer.play(Track…)`. With 2,000 cached names, contains-matching ahead of the library takes "play bloom" from a library song.
Fix — one pure `MusicSearch.resolve(query, library, stations)` used by both `ActionLayer` and the session:
> (1) query = "radio": the most recently played favourite, else the first favourite; with NO favourites, the library (a song called "Radio"), else the miss reply. (2) query ends " radio" or starts "radio ": favourites by exact name (with and without the word), cached directory exact name, cached tag = the rest (highest clickcount), cached name contains; then the library. (3) otherwise: favourite exact name → library exact (J5) → library contains → cached directory exact name. The directory is never contains-matched for a query without "radio".
Add to task 7: "`ActionLayer.playMusic` is changed (ADD to phase 03's part) to call this resolve and to start a station match through `MusicPlayer.playStations` when no controller exists."

## SHOULD-FIX

**D8 — Reconnect (§7.10 incomplete; L191-196, E8).** Two clocks: ExoPlayer's six retries (~15 s) then "60 s", while E8 asserts gave-up 60 000 ± 5 000 after `lost, retrying`. `WAKE_MODE_NETWORK` holds locks only while READY/BUFFERING (addendum §4); after the player error the state is IDLE, so a `Handler` retry with the screen off can stall. Wording:
> One clock: T0 = the first load error of a live item (`AnalyticsListener.onLoadError`), which writes `stream: lost, retrying`. On each `onPlayerError` the service re-prepares at 2/4/8/16/30 s; at T0 + 60 s it pauses and writes `gave up after 60000 ms`. From T0 until reconnect or give-up the service holds its own partial wake lock (65 s timeout). "Reconnecting…" and "This station isn't answering" ride session extras (`X_STREAM_STATE`), not metadata; the tile keeps the last title.
Pure: `StreamRetry.next(sinceLostMs, attempt)`.

**D9 — Live metadata (§7.2 incomplete; L157-162).** "The service supplies the station name itself" has no mechanism, and with `title` unset the queue rows (`MusicPlayer.kt:144-151`) and notification are blank; now-playing draws only title and artist (`MusicNowPlaying.kt:361`), so the station name disappears while a song title shows. Wording:
> The station item sets `albumTitle` AND `artist` to the station name, never `title`. The session's player wrapper (`KnownDurationPlayer`) overrides `getMediaMetadata()`: for a `station:` item with a null title, title = the station name. `MusicPlayer.readSession` falls back to `albumTitle` for a queue row with no title. Every directory string and StreamTitle passes pure `RadioText.shown(raw, max)` (`FilesIntents.lineSafe`'s rule, plus bidi/format characters; names ≤ 80, StreamTitle ≤ 120) before the tile, the notification, a diagnostics line or Tess's reply.

**D10 — HLS (§7.6): add it.** Wording: "`media3-exoplayer-hls` is added (224 KB; 9.8 % of the top 2,000; Rule 16). A row with `hls=1` gets `setMimeType(APPLICATION_M3U8)`. `stream: unsupported hls` and E3's branch are struck." **D11 — Playlist resolver (§7.7).** Wording: "The shell fetches and parses no playlist. **D12 — Redirects (§7.9): do not allow cross-protocol.** Wording replacing L692 and striking L722-723: "Media3's default is kept (`setAllowCrossProtocolRedirects` unset = false, as `video/VideoPlayback.kt:40`): same-scheme redirects are followed (≤ 20); a cross-scheme one fails the load → `stream: redirect refused`, no retry.
