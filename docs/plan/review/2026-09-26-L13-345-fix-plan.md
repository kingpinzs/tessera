## L13-4 — Back and Home die after a touch during the pivot (phase 01's part: StartActivity)

- Cause: the Back and Home collectors ran `pager.animateScrollToPage` (and Home's `scroll.animateScrollTo`) inside
  `collect { }` of a `LaunchedEffect`; a drag cancels the animation, the `CancellationException` ends the collect, and
  nothing collects `backEvents` / `homeEvents` again until StartActivity is recreated.
- Fix: the animations run in a child `launch` of the effect, so their cancellation ends only that child. The collectors
  live for the activity. A new diagnostics line, `[start] back: pivot interrupted by a touch` / `home: …`, says when it
  happens (it used to be silent).
- Gate: `qa/phase-13/scripts/l13_4_row.sh` — Back, Home and the drawn Back, each alone (control) and with a touch during
  its pivot; after each, the key twice more must take the app list to Start. Fails before (Back and Home dead after the
  touch), passes after.

## L13-5 — an overlay item runs when its overlay is removed under the finger (L13-2's rule: ui/components/ModalOverlay.kt)

- Cause: `overlayItem` treated `changedToUpIgnoreConsumed()` as a lift. Compose ends a gesture whose node leaves with a
  synthetic up that arrives already consumed (`onCancelPointerInput`), so Back while holding Pin to Start pinned the app.
- Fix: only an unconsumed up is a lift (the root consumes after its items in the same Main pass, so a real lift reaches
  the item unconsumed). The decision is `OverlayItemPress.lift(onItem, lifted)`, JVM-tested.
- Gate: `ModalOverlayTest` (+2: the removal's up runs nothing; a real lift still runs) — red on a stub that ignores
  `lifted`, green now; `qa/phase-13/scripts/l13_5_row.sh` — Back while holding Pin to Start pins nothing; the same press
  without Back pins on the lift. Fails before, passes after.

## L13-3 — a hold in the frame after Back is lost to the band's stale scrim (phase 02's band; the jump grids alike)

- Cause: Back only writes the overlay's state (`menu = null`, `gridOpen = false`); the overlay stays placed until the
  next frame, its full-screen scrim is the topmost hit, and Compose does not hit-test the list beneath it.
- Fix (the investigation's option A): `LocalOverlayActive` carries each overlay's open state, read at event time; the
  overlay's sibling-level node (`releaseInputWhenDismissed`: the app list's overlay box, Music's jump grid) shares pointer
  input with the siblings below while dismissed; the stale scrim (`modalOverlay`) and items (`overlayItem`) let a down go
  when dismissed. While open, nothing changes: the overlays stay modal (L13-2).
- Gate: `qa/phase-13/scripts/l13_3_row.sh` — 70 trials of hold, Back, hold at gap 0 (every second hold must open the
  band) and EDGE_RAPID's own host loop x3 (10 of 10 each). Fails before (the investigation lost 5 of 70), passes after.
  L13-2's `l13_2_row.sh` re-runs after it: the overlays still hold their gestures while open. `ModalOverlayTest` stays
  green.

### Amendment 2026-09-26 — option A failed its gate; the fix is now "unplace at once"

- Result on b2d44b7d (build 598ca8c2, `qa/phase-13/L13_3-fix1-598ca8c2/`): 70 of 70 trials, but EDGE_RAPID's host loop
  still lost holds (8, 8 and 10 of 10).
- Cause, from two diagnostic builds (`qa/phase-13/L13-3-diag-on-fix-e4dedc5e/`, `L13-3-diag2-row-events-5d1a37d5/`,
  the patch kept as `diag.patch`) and Compose UI 1.12.1's own bytecode:
  - Sharing did deliver the down to the row.
  - When a sibling shares, Compose appends the lower sibling's hits after its own (`HitTestResult.acceptHits`), and
    `HitPathTracker.addHitPath` chains that list parent to child. So the row's node sat *under* the stale overlay's
    nodes in the pointer's hit path.
  - Each hit node gets a detach listener that removes it and cancels its whole subtree
    (`NodeParent.removePointerInputModifierNode` then `Node.dispatchCancel`).
  - When the band left composition 4-6 ms after the down, the row got the synthetic consumed Release, and the hold
    ended as cancelled. The capture: `row event type=Release pressed=false prev=true consumed=true` at the band's
    `left composition` time.
  - Any fix that lets a stale overlay share a down fails this way.
- Fix (agent's call within Jeremy's "get them fixed"):
  - What changes: each overlay is drawn in `OverlayLayer` (ui/components/ModalOverlay.kt), which places its content only
    while the overlay is open, and reads that state while placing. The sharing node (`releaseInputWhenDismissed`) and
    the early returns on a stale down are gone.
  - Why it works: Compose runs pending layout before it hit-tests each touch (`AndroidComposeView.handleMotionEvent`
    calls `measureAndLayout` first), and it hit-tests only placed children (`InnerNodeCoordinator.hitTestChild`). A
    dismissal therefore takes the overlay out of the next touch's hit path altogether, and its later removal cancels
    nothing of the page's gesture.
  - Back handlers: they write through `dismissOverlay`, which applies the write at once
    (`Snapshot.sendApplyNotifications`). On the main thread, the layout invalidation runs synchronously
    (`AndroidComposeView`'s snapshot-observer executor), so even a touch already queued behind the Back sees the overlay
    unplaced.
  - Items: an item runs only while its overlay is open (`OverlayItemPress.lift(open)`). A real lift that comes after
    the dismissal and before the removal runs nothing.
- Gate: unchanged — `l13_3_row.sh` (70 trials + host loop x3), `l13_2_row.sh`, `l13_4_row.sh`, `l13_5_row.sh`.
  `ModalOverlayTest` +1 (`aLiftAfterTheOverlayWasDismissedRunsNothing`), red on a stub that ignores `open`
  (`qa/phase-13/unit/red-ModalOverlayTest-L13-3-open-stub*`), 12 of 12 green.

### Amendment 2026-09-26 (2) — after review round 1 (review/2026-09-26-L13-345-fix-review-a.md PASS, -b.md FAIL; triage review/2026-09-26-L13-345-fix-triage.md)

- **L13-4, reworked (note 3).**
  - The problem: b2d44b7d's child `launch` also changed the order of keys. Before, a second Back during the pivot
    waited in the flow's buffer and ran when the pivot ended, as Back on Start (the back-history launch). With the
    child launch, it came in mid-pivot and restarted the pivot, so Back on Start never ran.
  - The fix: the pivot stays inside the collector, and `untilInterrupted` (StartActivity) catches only the animation's
    interruption. It rethrows when the collector itself is cancelled (`currentCoroutineContext().ensureActive()`); this
    was the investigation's other option.
  - The log line is now `[start] back: animation interrupted` / `home: …`. It no longer says "by a touch", because
    another key's pivot interrupts it too (note 4).
  - Gate: `l13_4_row.sh` gains `twice`, two Backs at once from the app list. The row requires a `[back]` line and no
    `interrupted` line. Red on d6a364c8, the child-launch form (`qa/phase-13/L13_4-twice-red-d6a364c8/`: 20 passed,
    2 failed, and the slice shows `back: pivot interrupted by a touch` with no touch); green on 00244cec.
- **L13-3, the `open` check (note 1).** The reason given in the first amendment was wrong. Once `OverlayLayer` unplaces
  the overlay, the held item gets no events at all (`Node.dispatchMainEventPass` / `dispatchFinalEventPass` skip an
  unplaced node). The check matters only when the dismissal's write has not reached layout by the time the lift is
  dispatched. The comments are corrected.
- **Music's grid (note 5).** `dismissOverlay` wraps only the grid's Back handler, as in the app list. The tap-off no
  longer calls it, so it is never reached from inside `Recomposer.applyChanges` when the grid is removed under a finger.
- **Not in scope (note 6).** Music's hold menu and Now Playing's "more" menu are both `MusicMenu`: a full-screen scrim
  whose Back only writes the state. So by reading the code they have the same stale-scrim shape; this has not been
  reproduced on the device. New ledger row L13-6, for Jeremy to plan; not fixed here.
- **Note 2.** On d6a364c8 and later, the L13-5 row cannot separate the `lifted` rule from unplacement. The run that
  proves the rule is `qa/phase-13/L13_5-fix1-598ca8c2/`, with the unit tests.
- **L13-3, B1 (the evidence).** The row's trials and host loops pass the old build in some sessions, so they cannot
  carry "fixed" alone.
  - Window proof: a diagnostic build (e8a00dc6 = b572c6fe + `diag3.patch`, timing lines only, never committed) logs
    each Back, each OverlayLayer transition, each down and each band removal. In 10 host loops plus 40 probe trials,
