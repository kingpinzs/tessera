## Change Log (post-FINAL doc changes only)
- 2026-09-17: QA-GATE REVIEW OUTCOMES (phase 01, agent; the three reviews are in docs/plan/review/2026-09-17-phase01-*). Behaviour changed by the adversarial review of the Live Tile API trust surface, all in phase 01's own part: (1) a legacy badge broadcast whose sender did not share its identity is refused by default, because Android only names the sender when it opts in and no real sender does, which let any app set or clear any other app's badge; Settings > Live tile access has a switch to accept them again. (2) Accepted legacy badges honour both kill switches and a 30-per-minute limit, and badge expiry is swept every 15 minutes so a legacy count really lapses after three days (R5 rule 4). (3) A caller's image read gets a 3-second deadline and at most two run at once. (4) The image quota is checked before anything is written. (5) The Samsung badge authority is only read when a system package serves it. (6) Image errors no longer name the package that owns an authority. (7) One shared change URI replaces the per-app one, which let any app observe when a particular app updated its tile; the client library's changeUri returns it. (8) Stored image names must match the shell's own pattern and the app opts out of backup. (9) A master switch for the whole API. Also from the design review: a crossfading tile now cross-dissolves its faces instead of blanking the whole tile, and a slot whose assigned app is uninstalled or disabled shows unassigned rather than falling back to another handler (the Decisions and the Edge cases both say unassigned). Applied to phase-01 Decisions.
- 2026-09-17: RULING (Jeremy): "its not release phases so it does not matter if phase one is done move to phase two. so if a future phase covers something the current phase needs then dont worry about it and move on". A gap that a later phase's doc already owns is not a blocker for the current phase's gate: it is recorded in the phase's QA evidence with the phase that owns it, and the build moves on. First application: with show more tiles off, Start goes to two columns and the default layout's tiles in columns 4-6 fall outside the grid; phase 02 owns reflow (its Edge cases line "Changing show-more-tiles reflows a persisted layout without losing tiles" and its E9), so phase 01 records it and moves on.
- 2026-09-17: QA-GATE AGENT CALLS (phase 01 QA, agent; recorded because phase 01 is FINAL): (1) E20 method: the AOSP AVD ships with its lock screen disabled (`locksettings get-disabled` prints true and no KEYGUARD_SHOWN event is ever logged), so E20's lock and reboot steps first run `adb shell locksettings set-disabled false` and restore `set-disabled true` afterwards; the row's wording "the AVD's default swipe lock screen" assumed otherwise. (2) Back history window clarification: the activity that was showing when the keyguard appeared resumes again when the keyguard is dismissed; that resume is the same page coming back, not "another app opened", so it does not count until a different activity (Start, another app) has resumed in between; system surfaces (SystemUI, permission controller, installer, resolver, IMEs) neither count nor end it. This is how the Decisions line "after a lock, Back on Start does nothing until another app is opened" is implemented (E20 found the re-shown app counted). (3) E4 fixtures, per the Decisions swap rule: Fossify Music Player does not declare APP_MUSIC, so the second Music handler is Gramophone (Fossify Music Player stays installed as E8's playback fixture); Droid-ify does not declare APP_MARKET, so the second Store handler is F-Droid Basic; Fossify Gallery does not declare APP_GALLERY, and Photos' two handlers are the image's Gallery plus Aves; Organic Maps, Fossify Contacts and OpenContacts do not declare APP_MAPS / APP_CONTACTS, and a manifest scan of 265 F-Droid Navigation, Location Tracker, Phone & SMS and contact apps found no app declaring either (OsmAnd is the only APP_MAPS app), so Maps (OsmAnd) and People (the image's Contacts) run as one-handler categories with Calendar, and the 2+-handler rule is proven on Mail, Music, Store, Photos and Camera. (4) "New" caption wording: the Decisions line and E12 say the captioned name "moves up 7 epx", but R6 §5.1.5, which both cite, measured the captioned name's text centre 7 ± 1.4 epx above the icon centre, with uncaptioned names 2.75 epx below it (a move of about 9.75 epx); the build and E12 follow R6's definition (name text centre vs icon centre: −7 captioned, +2.75 uncaptioned, each ± 1.4 epx). (5) X25 build-start check result (owed by the bar rule, done during QA): with the soft keyboard up on a shell screen (AVD with show_ime_with_hard_keyboard set to 1), Android shows its own 3-button nav bar below the keyboard even though the shell hides the system bars, and the keyboard plus that bar cover the drawn W10M nav bar; the drawn bar returns when the keyboard hides. X25 is the covered form (H34; the phone's P7 checks One UI). Evidence qa/phase-01/X25. Applied to phase-01 Decisions.
