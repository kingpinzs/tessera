- 2026-09-21: ITEM 8, NEW (Jeremy: "the program list should have the last 5 ran programs and the last 3 installed programs"). Phase 01's part (the app list); built the same day. Two sections above the A-Z list: Recent (5) and Recently added (3). Last-run times come from UsageStatsManager, not from the shell's own launches, because "the last 5 ran programs" means what it says — an app opened from a notification or a link was still run — and the shell already declares PACKAGE_USAGE_STATS and already reads usage for Back on Start and the New caption, so this costs no new permission and no new checklist row. WITHOUT Usage access there is simply no Recent section and the diagnostics say why, which is what Back on Start already does rather than guess. Install times come from the catalog's own firstInstallTime: no store, no scan, right the first time Start draws. Decisions made and stated: an app with no usage record is LEFT OUT rather than sorted to the bottom, so a fresh phone shows two rows and not five padded with whatever is installed; an app whose install time is 0 (the platform reports that for some preinstalled entries) is left out of Recently added, because a zero would make the oldest thing on the phone look like the newest; ties break on the label so the order is stable between redraws; work and private-space apps are excluded from both sections, since the A-Z list puts them behind their own header and surfacing a private-space app at the very top is not something anyone asked for; and the shell itself never appears. The same app appears both at the top and in its letter group, so a section row carries its section in its LIST KEY and its TEST TAG (applist_recent_row:, applist_added_row:) — a LazyColumn refuses two items with one key, and two nodes with one tag would make an existing phase-01 driver tap whichever copy it found first. Section rows are not searchable: search reads the searchable list, and an app listed twice would come back twice for one query. The sections are built BEFORE the letter groups so the jump grid's indices are correct without being recounted. 11 unit tests, 320 in the suite, 0 failures. THIRD TIME FOR ONE TRAP: an AppEntry is a ComponentName and a UserHandle, and with returnDefaultValues both read null in a JVM test, so AppSections takes accessors rather than the type and its tests use plain values.

- 2026-09-21: ITEM 2 BUILT — the Weather tile's main face is the day's weather, animated (agent, Opus 5; phase 01's part, recorded because that doc is FINAL). Mechanism: TileContent gains a front face, one that REPLACES the tile's logo front instead of taking a turn behind it, because Weather is the one tile whose front is its content; publishing the conditions in the faces list as well would flip the tile between two identical pictures every 5 s.
