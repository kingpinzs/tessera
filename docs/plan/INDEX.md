The payload was never corrupt — the two archives hold the same 355 files with the same CRCs and sizes (content fingerprint cd277d7d… on both). `tools/fetch-speech.sh` built the archive with `zip -X`, and while `-X` drops the extra fields it does NOT drop the DOS date/time in each entry header, which zip writes in the BUILDER'S LOCAL TIMEZONE. - 2026-09-21: "APP NOT INSTALLED" ON EVERY UPDATE — ROOT CAUSE AND FIX (Jeremy: "When I tries to update to the latest it said not installed"). No signing secrets are set, so CI falls to the DEBUG variant, and a debug build is signed with ~/.android/debug.keystore, which the Android Gradle Plugin GENERATES when it is missing. A CI runner is clean every run, so builds 1, 2 and 3 each carry a different, randomly generated key, and Android refuses to update an app with a differently-signed one. Nothing in the failure says "different key", which is why it reads as a broken download. Phase 01's Decisions already require the opposite: "Phone installs are always release-signed and non-debuggable", so this is the delivery pipeline failing a rule that was already written, not a new requirement. THE REAL FIX is the four repository secrets the workflow has always supported (KEYSTORE_BASE64, KEYSTORE_PASSWORD, KEY_ALIAS, KEY_PASSWORD); with them every build shares one key and installs straight over the last. Jeremy generates the keystore himself so the private key and its password never pass through a transcript. UNTIL THEN, three changes so the failure can never again be silent: the APK's signing certificate SHA-256 is printed in the job summary AND in the release body, so a key change is visible before anyone downloads; a debug build says on its own release page that it CANNOT be installed over an earlier one and that the app must be uninstalled first; and the rolling latest release now deletes its old assets instead of collecting one APK per push, because three differently-signed builds on one page is how the wrong one gets picked. A tagged release is left alone.
